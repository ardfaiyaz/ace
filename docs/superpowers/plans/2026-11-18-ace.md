# Ace Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.
> **Execution chosen by the user:** superpowers:dispatching-parallel-agents. Task 1 runs first. Tasks 2 and 3 run in parallel (Agent A, Agent B). Task 4 runs last.

**Goal:** A browser-only page that scores a coding request against 6 gap rules and builds a copyable Markdown brief.

**Architecture:** Pure, tested functions in `src/lib/` (check rules, score, brief, samples), and one React component in `src/App.tsx` that holds the form state and renders the live result. Task 1 fixes the `check.ts` contract with stub bodies, so the UI can be built against it while the logic is written test-first.

**Tech Stack:** Vite, React and TypeScript (the `react-ts` template), plus Vitest. No other runtime dependencies.

**Spec:** `docs/superpowers/specs/2026-11-18-ace-design.md`

## Global Constraints

- Nothing leaves the browser: no fetch, AI, analytics, login or API keys.
- Font: Google Sans via a Google Fonts `<link>` in `index.html` (preconnect, `display=swap`), loading only weights 400, 500, 600 and 700.
- Font weights are used only through `--fw-title: 700`, `--fw-heading: 600`, `--fw-label: 500` and `--fw-body: 400`.
- Font stack: `"Google Sans", system-ui, -apple-system, "Segoe UI", sans-serif`. Monospace is used only in the brief textarea.
- Colors are used only through `--purple #6C3BAA`, `--white #FFFFFF`, `--purple-dark #57308A`, `--purple-ink #1E1033`, `--purple-tint #F3EEFA` and `--purple-border #E2D8F0`. No other hues and no gradients.
- Pass and fail are shown by icon + text (⚠ / ✓), never by color alone. All text meets WCAG AA (4.5:1).
- Every interactive element has a visible focus ring in `--purple`.
- The form is on the left and the result on the right, stacked below 768px.
- Agent A edits only `src/lib/**`. Agent B edits only `src/App.tsx` and `src/App.css`.

## Review Focus

1. **Whitespace-only fields** (`"   "`) count as empty for every rule. Covered in Task 2: `whitespace counts as empty`.
2. **Vague words inside other words** ("prefix", "fixture", "improvement") must not trigger the vague rule, and uppercase "FIX" must. Covered in Task 2: `vague matches whole words only`.
3. **Switching bug → feature** makes repro n/a, and the score updates without retyping. Covered in Task 2: `feature makes repro n/a`. Task 4 checks it by hand.
4. **An edited brief is not overwritten** by further typing until Reset is pressed. Checked by hand in Task 4, step 3.
5. **Clipboard denied or unavailable** shows a failure message, not "Copied!". Checked by hand in Task 4, step 3.

### Task 1: Scaffold + check.ts contract

**Files:**
- Create: the Vite `react-ts` template in the repo root, `src/lib/check.ts`, and `src/index.css` (tokens)
- Modify: `index.html` (font link, title "Ace"), `package.json` (Vitest, `"test": "vitest run"`)

**Interfaces:**
- Produces, in `src/lib/check.ts`:
  ```ts
  export type RequestType = 'bug' | 'feature';
  export interface AceRequest { type: RequestType; whatToChange: string; current: string; expected: string; repro: string; dontTouch: string; doneWhen: string; }
  export type CheckId = 'repro' | 'doneWhen' | 'vague' | 'area' | 'constraints' | 'expected';
  export interface CheckResult { id: CheckId; passed: boolean; applicable: boolean; label: string; question: string; }
  export const EMPTY_REQUEST: AceRequest; // type 'bug', all strings ''
  export function checkRequest(req: AceRequest): CheckResult[]; // always 6, in CheckId order above
  export function score(results: CheckResult[]): number;        // 0–6
  export function buildBrief(req: AceRequest): string;          // Markdown
  ```
- Produces, in `src/lib/samples.ts`: `export const VAGUE_SAMPLE: AceRequest; export const GOOD_SAMPLE: AceRequest;` (stub values in Task 1)

- [ ] **Step 3:** Put all tokens from Global Constraints into `:root` in `src/index.css`, together with the base font stack, body color `--purple-ink` and background `--white`. Add the font `<link>` to `index.html`.

### Task 2 (Agent A): Gap rules, brief, samples (TDD)

**Files:**
- Modify: `src/lib/check.ts` and `src/lib/samples.ts`
- Test: `src/lib/check.test.ts`

**Interfaces:** It consumes and produces exactly the Task 1 contract. It must not change any signature.

- [ ] **Step 1: Write the failing tests** in `check.test.ts`. Build a `base: AceRequest` with every field filled specifically and `type: 'bug'`, and a helper `get(req, id)` that returns the result with that id.
  - `returns six results in fixed order`: the ids equal `['repro','doneWhen','vague','area','constraints','expected']`.
  - `base request scores 6`: `score(checkRequest(base)) === 6`.
  - `bug without repro fails`: `get({...base, repro: ''}, 'repro').passed === false`.
  - `feature makes repro n/a`: with `type: 'feature', repro: ''`, the repro result is `applicable === false` and `passed === true`.
  - `missing done-when fails`: `doneWhen: ''` fails `doneWhen`.
  - `vague word without specifics fails`: `whatToChange: 'fix it', current: ''` fails `vague`. The same with `current` and `expected` filled passes.
  - `vague matches whole words only`: `'add a prefix and fixture improvement'` with `current: ''` passes `vague`. `'FIX the page'` with `current: ''` fails it. `'clean up the header'` with `current: ''` fails it.
  - `area detects file, route, area word`: `'edit Login.tsx'`, `'the /settings route'` and `'the checkout'` each pass `area` when every other field is `''`. The value `'make it nicer'` fails it.
  - `missing constraints fails`: `dontTouch: ''` fails `constraints`.
  - `expected empty or repeating fails`: `expected: ''` fails. `whatToChange: 'show an error on wrong password'` with `expected: 'show an error on wrong password'` fails. With `expected: 'red "Wrong password" text under the field, focus moves to it'` it passes.
  - `whitespace counts as empty`: `repro: '   '` fails `repro`.
  - `every failing result has a label and a question ending in ?`: for `checkRequest(EMPTY_REQUEST)`, every failed result has a non-empty `label`, and its `question` ends with `?`.
  - `samples score 2 and 6`: `score(checkRequest(VAGUE_SAMPLE)) === 2` and `score(checkRequest(GOOD_SAMPLE)) === 6`.
  - `vague sample text`: `VAGUE_SAMPLE` equals `{type:'bug', whatToChange:"fix the login page, it's broken", dontTouch:'signup', current:'', expected:'', repro:'', doneWhen:''}`.
  - `brief has every section and None specified`: `buildBrief(VAGUE_SAMPLE)` contains `## What to change`, `## Current behavior`, `## Expected behavior`, `## Repro steps`, `## Don't touch`, `## Done when`, and `None specified`. For a feature request it leaves out `## Repro steps`.
- [ ] **Step 2: Run** `npx vitest run src/lib`. Expected: FAIL (stubs).
- [ ] **Step 3: Implement** the rules exactly as written in the spec under "Gap rules":
  - Trim every field first.
  - **Vague:** a case-insensitive whole-word regex for `fix|better|clean up|improve`.
  - **Area:** a file name `/\b[\w-]+\.[a-z]{2,4}\b/i`, a route `/(^|\s)\/[\w-]+/`, or the spec's area-word list matched as whole words, across every text field.
  - **Expected repeats:** a small stopword set. The check fails when 80% or more of the meaningful words in `expected` appear in `whatToChange`.
  - **Brief:** starts with `# Task brief (bug|feature)` and ends with `Before writing code, restate the expected result for each "Done when" item.`
  - Write `GOOD_SAMPLE` as a specific `/login` wrong-password bug.
- [ ] **Step 4: Run** `npx vitest run src/lib`. Expected: all PASS.
- [ ] **Step 5: Commit:** `feat: gap rules, brief and samples with tests`.

### Task 3 (Agent B): UI in App.tsx (the /prototype winner)

**Files:**
- Modify: `src/App.tsx` and `src/App.css`

**Interfaces:** It consumes the Task 1 contract only (`AceRequest`, `EMPTY_REQUEST`, `checkRequest`, `score`, `buildBrief`, `VAGUE_SAMPLE` and `GOOD_SAMPLE`). It must not edit `src/lib/**`.

- [ ] **Step 1:** Write the header: the title "Ace" (`--fw-title`), the tagline "Catch vague requests before your AI codes them", the buttons "Load vague sample" and "Load good sample", and a line calling Ace a checklist, not a judge.
- [ ] **Step 2:** Write the form, held in one `useState<AceRequest>`:
  - a Bug / Feature radio group in a `fieldset` with a `legend`
  - six labelled fields: "What to change", "Current behavior", "Expected behavior", "Repro steps" (shown only for bugs), "Don't touch" and "Done when"
  - every field linked to its label with `htmlFor`/`id`
- [ ] **Step 3:** Write the result panel, laid out as the /prototype winner:
  - **Score:** "Clarity: N / 6" with a bar. Use `<meter>` or `role="meter"` with `aria-valuenow`.
  - **Warnings:** a list with ⚠ + label + question for failed results and ✓ + label for passed ones. An n/a result shows "n/a for features".
  - **Status line:** `aria-live="polite"`, announcing the score.
- [ ] **Step 4:** Write the brief:
  - **Textarea:** labelled "Task brief", monospace. Its value is `buildBrief(req)` until the user edits it.
  - **After an edit:** show "Edited · Reset", where Reset goes back to the generated brief. Loading a sample also resets it.
  - **Copy button:** uses `navigator.clipboard.writeText`. It shows "Copied!" for 2s in an `aria-live` region, or "Copy failed, select the text and press Ctrl+C" if writing fails or is unavailable.
- [ ] **Step 5:** Style `App.css` with the tokens only:
  - two columns at 768px and wider, stacked below that
  - thin `--purple-border` borders and minimal shadow
  - a `:focus-visible` outline of 2px solid `var(--purple)` with a 2px offset
- [ ] **Step 6:** Verify. `npx tsc --noEmit` passes, and `npm run dev` renders against the stubs without console errors.
- [ ] **Step 7:** Commit: `feat: Ace UI`.
